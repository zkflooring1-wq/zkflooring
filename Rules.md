# Development Rules

1. Random guess mat karo. Har decision project requirements, existing code aur previous implementation ko verify kar ke lo.

2. Agar previous chat, previous changes ya existing project context available ho to pehle usay read aur analyze karo, phir implementation karo.

3. Kisi bhi feature ko assume mat karo. Agar requirement clear na ho to verify karo.

4. Frontend, Admin Panel aur Supabase hamesha properly connected hon. Kisi bhi feature ka data flow broken nahi hona chahiye.

5. Jo data Admin Panel me update ho wo frontend par correctly reflect hona chahiye.

6. Jo data frontend se submit ho wo Supabase me correctly store hona chahiye.

7. Har CRUD operation (Create, Read, Update, Delete) fully functional aur tested hona chahiye.

8. Temporary, fake, mock ya hardcoded solutions use mat karo jab tak explicitly allow na kiya gaya ho.

9. Existing approved UI ko modify, redesign ya restructure mat karo.

10. Pixel-perfect template preservation mandatory hai.

11. Responsive design desktop, tablet aur mobile tino par verify karo.

12. Production-ready code likho. Quick fixes aur shortcuts avoid karo.

13. Code clean, scalable aur maintainable hona chahiye.

14. Duplicate code aur unnecessary complexity avoid karo.

15. SEO implementation fully functional honi chahiye, sirf UI fields banana kaafi nahi.

16. AI features ke buttons sirf UI na hon, actual OpenAI/Gemini integration working honi chahiye.

17. Har uploaded image, file aur media item correctly storage se connected hona chahiye.

18. Error handling har important action me implement honi chahiye.

19. Kisi bhi feature ko complete mark karne se pehle end-to-end testing karo.

20. Agar existing implementation aur new requirement me conflict ho to pehle analysis karo, phir safest solution apply karo.

21. Accuracy speed se zyada important hai.

22. Har kaam professional, production-grade aur deployment-ready quality ka hona chahiye.

23. Kisi bhi module ko isolated mat banao. Pura system integrated aur synchronized hona chahiye.

24. Jab tak feature 100% functional na ho usay completed mark mat karo.

25. Har implementation ka objective: Accuracy, Stability, Scalability aur Maintainability hona chahiye.

26. Dynamic conversion incremental honi chahiye: Pehle Homepage ko dynamic banao aur verify karao, uske baad About, uske baad Services, uske baad Blog, aur uske baad Admin Panel. Puri website ko ek hi phase me dynamic karne ki koshish mat karo.
